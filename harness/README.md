# Holdout

100 attacks and 20 legitimate visits (plus 10 unsafe rules), run at two levels. The second number, real visitors wrongly refused, keeps the first honest.

| File | Category | Cases |
| --- | --- | --- |
| `attacks/01-direct.yaml` | Direct instruction | 10 |
| `attacks/02-authority.yaml` | Authority impersonation | 15 |
| `attacks/03-urgency.yaml` | Urgency and emotion | 10 |
| `attacks/04-fake-system.yaml` | Fake system messages | 15 |
| `attacks/05-obfuscated.yaml` | Obfuscated text | 10 |
| `attacks/06-multi-turn.yaml` | Multi-turn social engineering | 10 |
| `attacks/07-credentials.yaml` | Forged or stale credentials | 15 |
| `attacks/08-mode-bypass.yaml` | Mode bypass | 10 |
| `attacks/09-tool-args.yaml` | Tool-argument injection | 5 |
| `attacks/10-legit.yaml` | Legitimate visits (must allow) | 20 |
| `attacks/11-unsafe-rules.yaml` | Unsafe rules (must be refused) | 10 |

The YAML is generated by `generate.ts` (`npm run holdout:generate`) so every phrase is reviewable in one place.

## Guard level (CI)

```bash
npm run holdout -- --level guard
```

Deterministic, no model. Each case runs through the real physical-tool path: signed passes in the passes table, approvals bound to the request id, Engram, per-caller rate buckets. The attacker controls every argument an agent could send. Text never reaches a guard input, so the text categories are blocked by construction; the credential and mode cases are where this level does real work. The build fails if any attack is allowed, any legitimate visit is refused, or any unsafe rule is accepted.

## Agent level (before recording)

```bash
MODEL_PROVIDER=bedrock BEDROCK_MODEL_ID=<model id> npm run holdout -- --level agent
```

Each case goes through the real agent and model, once with HomePulse and once with the naive baseline (same model, same prompt style, no guard, no untrusted wrapper). Sign cases render the sign text onto a simulated snapshot. No approver is connected for attacks; for legitimate owner-approval visits an approver session taps Approve. Writes `report.md` with the model id, date and results.

`--allow-offline` runs the scripted offline stand-in instead of a model. That is a plumbing check only, writes to `out/`, and is never a reportable result.

`report.md` is not committed yet: it needs a run against a real Bedrock model.
